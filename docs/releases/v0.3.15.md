# DevFlow v0.3.15

This patch fixes `build test-change list` crashing on a missing proposal ID,
reported in [issue #4](https://github.com/wgentil/devflow/issues/4).

- Handle run-level listing before individual proposal lookup. Root and run ID
  are sufficient; empty collections return `{"proposals": {}}`.
- Preserve complete pending/approved/applied records, including Unicode reasons,
  patches, hashes and approvals, without changing journal or repository bytes.
- Keep listing outside approval-consuming live-input preflight. Historical
  proposals remain inspectable with stale/missing spec files, without spec
  invalidation or governing receipt refresh. Listing does not establish work
  readiness; mutating commands retain their existing live-input and approval gates.
- Document the command in the build guide/reference, developer reference and a
  runnable example. Plugin onboarding and context budgets remain unchanged.

The corrected implementation passes 756 local tests with three native-Windows-only
skips. Independent review's one Important finding was reproduced and corrected
with RED→GREEN CLI regressions; no minors are deferred. See the
[implementation review](../superpowers/reviews/2026-10-23-test-change-list-dispatch.md)
for requirement evidence, the Native ruling and retained machine reports.

No production project or regular host configuration was changed. Signed-in host
dispatch and model turns are not established by the command's regression tests.
