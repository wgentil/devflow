# DevFlow v0.3.12

This patch fixes context preparation on large control roots, including the
reported five-second `prepare-context` timeout in [issue #2](https://github.com/wgentil/devflow/issues/2).

- Reuse authoritative journal state during live input preflight and pass only
  scoped task inputs to the bounded composition worker. The worker does not replay
  project history; the existing five-second deadline remains unchanged.
- Bind live specification, governing, grounding, repository and host inputs through
  the locked attempt commit. Changed or newly appearing inputs block stale work
  without consuming its operation retry key.
- Preserve selected requirements and applicable shared rules while excluding
  unrelated history. Remove optional context values before reporting mandatory
  overflow, and report exact UTF-8 byte components and recovery guidance.
- Update workflow/build guidance, host documentation and troubleshooting, with a
  disposable benchmark for contributors. Plugin onboarding is unchanged.

The final implementation suite passed 688 tests (687 passed, one Windows skip).
Independent review found two Important issues; both were reproduced and corrected
with RED→GREEN regressions and a full passing suite. See the
[verification report](../superpowers/reviews/2026-10-21-large-control-root-context.md).

A local synthetic fixture with 4,370 events, 40 historical runs and 79.7 MB of
state completed `run next` in 2.05 seconds, including 129 ms in the worker. Exact
retry retained one token and selected task content matched a small project.
These measurements do not establish performance on the reporter's project.
Ordinary journal replay still grows with history. Some public-hook/reverification
diagnostics omit initial replay time; measure full CLI latency on those paths.
Native Windows and installed live-provider workflows remain unverified.
