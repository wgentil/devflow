# DevFlow v0.3.11

This release improves recovery within a single development run and surfaces governing approval during setup.

- Reverify stale completed code items with a fresh attempt and GREEN proof, keeping implementation files in place.
- Explicitly reuse qualifying recorded RED evidence with matching plan, specification, governing, item, repository, test and runner contracts.
- Reopen only the reviewed item after valid item-bound request-changes; resumed guidance routes pending corrections to implementation.
- Require explicit proof-bound passing results and provide clearer reviewer identity and finding diagnostics.
- Allow unrelated work during complete scoped item review while binding packaged source, test, staged and dirty inputs. Incomplete scopes retain whole-tree checks.
- Return exact governing approval proposals during setup without automatic approval or duplicate organization owners.
- Add runner/prior-finding examples and cached-client, API and asset-versioning prompts within existing interview topics.

Exact-head verification remains required. Legacy RED without complete provenance cannot be explicitly reused. Whole-branch and acceptance reviews remain conservative. No framework-specific runner adapters, automatic completion statistics or production deployment gates were added.

The implementation received independent review. Reproduced routing and scoped-input gaps were corrected with RED→GREEN regressions. The final implementation suite passed 632 tests with one platform skip. See the [verification report](../superpowers/reviews/2026-10-20-fresh-run-workflow-recovery.md). Live provider workflows and Windows/WSL2 remain unverified.
