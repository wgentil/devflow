# DevFlow v0.3.14

This patch fixes unnecessary Claude prompt-hook work and timeout blocking
reported by a fresh Bandpick run in [issue #3](https://github.com/wgentil/devflow/issues/3).

- Skip journal/snapshot reads for SessionStart and UserPromptSubmit when the
  session has no usable attachment hints. Malformed locator/index shapes receive
  normal repair handling instead of parser crashes.
- Reuse one authoritative journal read during attached refresh, preserving live
  preparation and freshness checks. The remaining replay still scales with history.
- Let UserPromptSubmit continue after a helper timeout, with a best-effort warning
  and no partial context output. Explicit blocks, other mandatory failures and
  task-completion timeouts remain blocking. Existing 8/10-second limits are unchanged.

The corrected implementation passes 749 tests per full platform suite on Ubuntu,
macOS and Windows Python 3.11/latest, plus 22 legacy CP1252 tests on both Windows
profiles. Exact candidate Codex/Claude installation, startup, protocol and seventeen
installed hook-script checks pass. One Important independent-review finding was
reproduced and fixed with RED→GREEN tests; there are no deferred minors.

A read-only real Bandpick fresh-session evaluation changed from 7.575s with one
replay to about 0.007s with zero replays; the adapter took about 0.097s. These are
observed timings, not a universal latency guarantee. Prompt acceptance does not
establish required-context readiness. Ask the harness to check attachment and
refresh required context before workflow work.
