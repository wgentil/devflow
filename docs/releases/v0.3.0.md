# DevFlow v0.3.0

DevFlow now stores approved feature specifications as searchable JSON and Markdown
files in the project repository. Approval binds the exact file pair; file drift
blocks dependent work until renewed review. Existing journal-only specifications
remain readable and have an explicit migration path that creates a candidate for
fresh approval.

Organization and project repositories can hold architecture, coding standards,
application contracts, test strategy and design-system rules. Projects inherit
organization rules and override named rule IDs. DevFlow tracks applicable file
digests and provenance, requires separate exact-diff approval for changed
governing documents, and blocks a stale organization checkout. Changed policy
requires explicit plan impact reassessment and a fresh run; the old run and its
evidence remain available for audit.

Guided setup starts in an existing Git project. It can use project-only
documents, attach an accessible organization Git URL, or create a local
organization repository at an explicit location. No folders, shell variables or
direct Python commands are required from plugin users. Creating a remote
organization repository and native Codex plugin installation remain outside the
verified setup path.

The Claude Code marketplace is hosted at the private
[`wgentil/devflow`](https://github.com/wgentil/devflow) repository. Users with
access can install or upgrade the plugin when they choose. Cross-host handoff
requires matching installed DevFlow release identities. See the
[setup guide](../setup-and-usage.md) for installation, initialization, upgrade
and recovery instructions.
