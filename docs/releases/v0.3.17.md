# DevFlow v0.3.17

This maintenance release publishes fresh validation evidence for previously
shipped large-project responsiveness and archive-backed storage behavior.
Package version metadata advances to 0.3.17; there are no new workflow features,
runtime algorithm changes, storage migrations or protocol/schema changes.

- [Batch 2 validation](../superpowers/reviews/2026-11-03-batch-2-large-root-validation.md)
  covers issues [#2](https://github.com/wgentil/devflow/issues/2) and
  [#3](https://github.com/wgentil/devflow/issues/3): large legacy-root `run next`,
  safe exact retry, read-only fresh-session prompt latency and retained blocking
  for required context and mapped completion.
- [Batch 3 validation](../superpowers/reviews/2026-11-03-batch-3-storage-maintenance-validation.md)
  covers [#5](https://github.com/wgentil/devflow/issues/5): public backup,
  conversion, compaction and GC on owned fixtures, complete logical/raw-event
  parity, exact retries, unknown-content retention and 10/1,000-run scale checks.
- The controlled 100 MiB review corpus retained complete logical/audit parity
  with 3,782 bytes of hot logical payload. Total root file bytes increased by
  473,332 because verified backups remain retained; this is working-set reduction,
  not a promise of total disk shrinkage or arbitrary-data compression.

The batch measurements are bound to their original v0.3.16 runtime source.
Exact v0.3.17 package, installation and platform evidence is recorded separately
in the [release validation report](v0.3.17-validation.md).

Existing legacy roots still require explicit verified conversion. No production
root was backed up, converted, compacted or garbage collected by these batches.
Installing this release does not perform maintenance or close GitHub issues.
Hosts choose upgrades separately and require matching installed package identity
before cross-host work. Signed-in model/event/handoff acceptance remains a
separate gate from automated startup/protocol/hook-script checks.
