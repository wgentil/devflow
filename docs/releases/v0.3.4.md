# DevFlow v0.3.4

This release adds an opt-in GitHub pull-request review path. After a user chooses
PR delivery, DevFlow opens a pending PR, builds a current full-diff review package,
requires an independent reviewer, and publishes a concise report and exact-head
`devflow/pr-review` status. Changes requested trigger bounded implementer rework
and renewed verification; unresolved human decisions and stale evidence keep the
status non-passing. Existing direct delivery paths remain available.

PR setup configures a dedicated required-status ruleset with named trusted
direct-push bypass actors. That bypass also applies in GitHub outside DevFlow's PR
workflow, so grant it only to actors the repository trusts. External PR changes
require a manual DevFlow sync and fresh review; DevFlow does not run a webhook
service and does not merge the PR.

The full 471-test Python suite passed on macOS with one skipped test. Claude
marketplace validation passed. GitHub adapter behavior was covered with fixtures,
but a live temporary-repository test of rulesets, PR comments, statuses, and
bypass behavior was not run for this release. Native Windows and WSL2 remain
outside the supported host matrix; see the [validation matrix](../windows-validation.md).
