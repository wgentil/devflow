# DevFlow v0.3.17 release plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Push the completed local batches and publish v0.3.17 with exact-version release evidence.

**Architecture:** Follow the existing distribution/release contract. Change version metadata and current-release documentation only, verify the exact candidate locally and in existing CI/install gates, then retain evidence and publish the authorized main/tag/release.

**Tech Stack:** Existing GitHub CLI, Git, Python/unittest, Codex and Claude package validators.

**Spec:** [Existing release contract](../../github-distribution.md#prepare-a-release), established [v0.3.16 release procedure](../../releases/v0.3.16-validation.md), and the user's explicit instruction to push local changes and create a release. This is routine authorized delivery of already reviewed work, not new feature design.

## Global Constraints

- Baseline: `7daecd49f82183e3276ed076d5b94d0ade9e6af6`; both completed validation batches are included.
- Use the clean managed workspace; preserve main's existing AGENTS.md edit byte-for-byte and keep it uncommitted.
- Version is 0.3.17 in all three manifests and the version assertion; logical schema 1, storage formats 1/2 and host protocol 1 remain unchanged.
- No runtime feature change, production control-root maintenance, regular host configuration change, paid model probe or issue comment/closure.
- User authorization covers pushing the existing/main release commits, local release integration, tag and GitHub release publication. Do not force-push or replace an existing tag/release.
- Installed-host checks use disposable configurations; no signed-in model/event/handoff acceptance is inferred from startup/protocol/hook checks.
- Record exact source/fingerprint and real CI statuses. Documentation/evidence-only follow-up may use established `[skip ci]` only after fingerprint equality is confirmed.

## Review Focus

- All manifests, public version output and current-release links must agree on 0.3.17.
- Notes must describe validation of previously shipped fixes, not invent new runtime fixes or production maintenance.
- Tests and installed packages must bind to the exact new package fingerprint, with actual failures/skips/limits retained.
- GitHub/main publication must preserve the user's dirty edit and avoid overwriting remote work, prior tags or release assets.
- Final evidence amendments must not change fingerprinted files after tested-source identity is established.
